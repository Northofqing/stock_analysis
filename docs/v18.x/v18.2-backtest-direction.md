## 三、关键模块详细设计

### 3.1 事件驱动回测引擎

**为什么需要事件驱动？**

```
向量化回测的问题:
├── 信号是在"收盘后"计算的还是"盘中"计算的？
├── 多信号同时触发时，订单执行顺序是什么？
├── 涨跌停时，订单能否成交？
└── 持仓期间，突发事件如何处理？

事件驱动的优势:
├── 精确模拟真实交易流程
├── 信号 → 订单 → 成交 → 持仓 → 结算
├── 可加入延时、流动性、滑点等真实约束
└── 可追溯每一笔决策的上下文
```

**事件流设计:**

```rust
// 每日事件序列
fn process_day(engine: &mut BacktestEngine, date: Date, data: &DayData) {
    // 1. 开盘前: 读取涨跌停/停牌状态
    engine.update_market_state(data);

    // 2. 盘中: 生成信号
    for signal in engine.generate_signals(date, data) {
        // 3. 订单生成
        let order = engine.create_order(signal);

        // 4. 订单执行模拟
        let fill = engine.simulate_fill(order, data);

        // 5. 更新持仓
        if let Some(fill) = fill {
            engine.update_position(fill);
        }

        // 6. 风控检查
        if engine.risk_check().is_rejected() {
            engine.cancel_pending_orders();
        }
    }

    // 7. 收盘: 记录净值
    engine.record_nav(date);
}
```

### 3.2 滑点/佣金/冲击成本

```rust
struct CostModel {
    commission_rate: f64,    // 印花税+佣金 (约0.001)
    slippage_bps: f64,       // 滑点 (约1-5bp)
    market_impact: bool,
}

// 订单成交价格计算
fn calculate_fill_price(
    order: &Order,
    day_data: &DayData,
    cost_model: &CostModel,
) -> FillResult {
    let base_price = match order.price_type {
        PriceType::Market => day_data.open,     // 市价单用开盘价
        PriceType::Limit(price) => price,
    };

    // 滑点: 基于订单量和市场波动率
    let slippage = if cost_model.market_impact {
        calculate_market_impact(order, day_data, base_price)
    } else {
        base_price * cost_model.slippage_bps / 10000.0
    };

    // 佣金
    let commission = base_price * order.qty as f64 * cost_model.commission_rate;

    let fill_price = base_price + slippage;
    let total_cost = commission + slippage * order.qty as f64;

    FillResult { fill_price, commission, total_cost }
}

// 大单冲击成本 (Almgren-Chriss模型简化版)
fn calculate_market_impact(order: &Order, data: &DayData, base_price: f64) -> f64 {
    let participation_rate = order.qty as f64 / data.volume;
    let volatility = data.high / data.low - 1.0;

    // 冲击成本 ≈ volatility * sqrt(participation_rate)
    let impact = volatility * (participation_rate.sqrt());

    base_price * impact
}
```

### 3.3 涨跌停处理

```rust
enum LimitUpResult {
    CanTrade { fill_rate: f64, reason: String },
    CannotTrade { reason: LimitUpReason },
}

enum LimitUpReason {
    LimitUp,      // 涨停，无法买入
    LimitDown,    // 跌停，无法卖出
    Suspended,    // 停牌
}

fn check_order_feasibility(
    order: &Order,
    day_data: &DayData,
    config: &EngineConfig,
) -> LimitUpResult {
    let price = day_data.close;
    let limit_up = price * 1.10;  // 10%涨跌停
    let limit_down = price * 0.90;

    match config.limit_up_behavior {
        LimitUpBehavior::Skip => {
            if day_data.high >= limit_up && order.side == Side::Buy {
                return LimitUpResult::CannotTrade(LimitUpReason::LimitUp);
            }
            if day_data.low <= limit_down && order.side == Side::Sell {
                return LimitUpResult::CannotTrade(LimitUpReason::LimitDown);
            }
        }
        LimitUpBehavior::PartialFill { fill_rate } => {
            // 部分成交模拟
            if day_data.high >= limit_up && order.side == Side::Buy {
                return LimitUpResult::CanTrade {
                    fill_rate,
                    reason: format!("涨停买入，实际成交{}%", fill_rate * 100.0),
                };
            }
        }
        LimitUpBehavior::NextOpen => {
            // 涨跌停时，次日开盘执行
        }
    }

    LimitUpResult::CanTrade { fill_rate: 1.0, reason: "正常成交".into() }
}
```

```rust
impl FactorStats {
    // 计算因子IC (Rank IC / Pearson IC)
    fn calculate_ic(&self, factor_values: &[f64], returns: &[f64]) -> f64 {
        // Pearson相关系数
        let n = factor_values.len().min(returns.len());
        pearson_correlation(&factor_values[..n], &returns[..n])
    }

    // 因子衰减监控
    fn check_decay(&self) -> bool {
        // 如果最近60天IR < 0.3，标记为衰减
        self.ir < 0.3
    }
}
```

### 3.5 业绩归因

```rust
// Brinson归因
struct BrinsonAttribution {
    // 配置效应: 超配行业 vs 基准行业
    allocation_effect: f64,
    // 选股效应: 行业内选股alpha
    selection_effect: f64,
    // 交互效应: 配置×选股
    interaction_effect: f64,
}

// 计算Brinson归因
fn brinson_attribution(
    portfolio: &Portfolio,
    benchmark: &Portfolio,
    sector_mapping: &HashMap<String, String>,
) -> BrinsonAttribution {
    // 按行业分组
    let sectors: HashSet<_> = sector_mapping.values().collect();

    let mut allocation = 0.0;
    let mut selection = 0.0;
    let mut interaction = 0.0;

    for sector in sectors {
        let p_weight = portfolio.sector_weight(sector);
        let b_weight = benchmark.sector_weight(sector);
        let p_return = portfolio.sector_return(sector);
        let b_return = benchmark.sector_return(sector);

        // 配置效应: (组合权重 - 基准权重) × 基准收益
        allocation += (p_weight - b_weight) * b_return;

        // 选股效应: 组合权重 × (组合收益 - 基准收益)
        selection += p_weight * (p_return - b_return);

        // 交互效应
        interaction += (p_weight - b_weight) * (p_return - b_return);
    }

    BrinsonAttribution { allocation, selection, interaction }
}

// 完整业绩报告
struct BacktestReport {

    calmar: f64,

    alpha: f64,
    beta: f64,
    tracking_error: f64,
    information_ratio: f64,

    brinson: BrinsonAttribution,

    avg_profit_per_trade: f64,
```

### 7.1 事件驱动回测主循环

```rust
pub struct EventDrivenBacktest {
    config: EngineConfig,
    positions: HashMap<String, Position>,
    cash: f64,
    history: Vec<DailyNav>,
    trades: Vec<TradeRecord>,
}

impl EventDrivenBacktest {
    pub fn run(&mut self, data: &[StockHistory]) -> BacktestResult {
        // 按日期排序
        let mut all_dates: Vec<_> = data.iter()
            .flat_map(|(code, _, ks)| ks.iter().map(|k| k.date))
            .collect::<BTreeSet<_>>()
            .into_iter()
            .collect();

        for date in all_dates {
            for (code, name, klines) in data {
                if let Some(kline) = self.get_kline(klines, date) {
                    // 1. 生成信号
                    let signal = self.generate_signal(code, name, kline);

                    // 2. 执行订单
                    if let Some(signal) = signal {
                        self.execute_signal(&signal, kline);
                    }
                }
            }

            // 3. 收盘记录
            self.record_nav(date);
        }

        self.build_result()
    }

    fn execute_signal(&mut self, signal: &Signal, kline: &KlineData) {
        let order = self.create_order(signal, kline);

        // 模拟成交
        let fill = self.simulate_fill(&order, kline);

        if let Some(fill) = fill {
            // 更新持仓和现金
            self.update_position(&fill);
            self.cash -= fill.filled_value + fill.commission;
        }
    }

    fn simulate_fill(&self, order: &Order, kline: &KlineData) -> Option<Fill> {
        // 检查涨跌停
        let limit = kline.close * 1.10;

        if order.side == Side::Buy && kline.high >= limit {
            return None; // 涨停无法买入
        }

        // 计算滑点
        let slippage = self.config.slippage_bps / 10000.0 * kline.close;
        let fill_price = kline.close + slippage;

        // 计算佣金
        let commission = fill_price * order.qty as f64 * self.config.commission_rate;

        Some(Fill {
            order_id: order.id.clone(),
            price: fill_price,
            qty: order.qty,
            commission,
            slippage,
        })
    }
}
```

**核心原则:** 回测是为了验证策略有效性，不是为了"跑出好结果"。任何回测都要问自己：这个结果能经受住样本外检验吗？
