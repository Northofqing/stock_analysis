## 取消与保留

本次以用户自行控制的本地运行环境为前提，不建设多用户安全平台，也不再等待身份发行方、PAM身份接线、角色管理员或签名信任根才能开发推送业务。

| 本次不做 | 仍要做 | 原因 |
| --- | --- | --- |
| 新增用户登录、RBAC、多角色授权、双人审批 | 用户显式执行的本地操作；危险操作的确认与结果记录 | 单用户不需要角色体系，但不等于允许程序擅自部署、删除或重发 |
| 外部身份发行方、规范操作者认证、批准凭证撤销/防重放基础设施 | 固定任务/业务日/运行/效果编号，任务锁和过期执行者拒绝 | 定时器、手动入口和重启恢复即使都由同一人使用，也可能撞在一起 |
| 作为本地执行前置的制品签名信任链、认证broker与多actor授权服务 | 明确的本地配置、同库事务、配置一致性检查、唯一执行权 | 不将“身份已认证”作为启动条件，仍须防止错库、重复执行和并发写入 |
| 将本地观察包装成来源/部署的密码学认证 | 真实来源、时间、完整性、数据缺失与schema/原字节校验 | 不认证操作者，不代表可以编造行情、把缺字段当空池或接受损坏记录 |

仍保留凭据脱敏、报告目录限制、符号链接/路径越界防护和基本文件权限检查。这些保护用户自己的数据，不需要外部管理员、身份发行方或证书服务。

## 本地接线合同

1. 新入口明确称为“单用户本地运行”，不称为已认证Production。只接受本地显式配置和已知任务映射，固定Unit、producer、业务日、来源合同、模板和目标集合。缺必需配置返回具体缺项；不拿测试常量或可跳过PAM的Ok充当认证证明。
2. 复用同一个BusinessIntentStore连接；本地入口不公开raw connection、任意SQL或可任意选库的业务callback。不直接把旧认证构造器的ProductionRefused改成无条件Ok，旧认证实现先保留，不进行全仓删除/重写。
3. 运行编号仅用于追踪和防重，不证明“谁批准了”。每个实际效果前的持久begin、返回后的result、原始报告和任务锁仍须实现；旧执行者/重复入口被拒绝，未知结果不自动重发。
4. 报告生成、文件保存、渠道弱接受和强确认仍是不同事实。此次没有修改必达渠道选择或完成策略，也没有把Accepted/Unknown升级为已送达、已读或Completed。
5. 现有推送继续保留，新的本地路径完成定向验证后再安排切换。此次需求变更不授权读取真实.env/生产库、启动或观察monitor、调用实际渠道、部署或自动发送测试消息。
