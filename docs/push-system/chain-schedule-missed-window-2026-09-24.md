# 产业链定时报告错过窗口的记录边界

盘前产业链仅在本地交易日 09:05–09:14 启动新报告；盘后仅在 15:30–15:34 启动。monitor 在入口处重读时钟，`run_scheduled_chain_analysis` 再次检查日期与窗口，防止循环前段耗时后用旧时钟启动新采集。

窗口结束后，同一交易日的 monitor tick 会检查调度账本：若该时段没有已记录的渠道弱接受，且最新状态为 `Ready`（包括未尝试或人工裁定可重试），则在 `chain_schedule_miss_v1` 为该时段与日期写一条不可变记录；重启后不会重复写。`sending` 是发送结果不明，须人工核对；`weak_accepted` 和 `manual_delivered` 已关闭，均不记为错过窗口。漏记本身不调用来源、模型或通知渠道，也不改变发送状态。

只读查看命令：

```bash
cargo run --bin chain_schedule_resolve -- --phase postclose --date 2026-09-24
```

有漏记时会显示 `missed_window_at`（含时区）、最近一次尝试编号和状态。`status=Ready` 同时出现漏记，表示调度窗口已过、没有已确认的弱接受，**不表示可以在窗口外重新生成并发送报告**。在错误数据库路径上，查看命令仍报错，不会静默创建空历史。

本功能只有在 monitor 于对应自然日、截止时间之后运行时才会写漏记；如果机器直到次日仍未启动，过去日期不会凭空补造监测事实。历史报告的受控恢复仍需固定当时来源、模型与报告原字节，并按[盘后持久恢复计划](../superpowers/plans/2026-09-11-chain-post-close-recovery.md)完成后续接线。当前弱渠道接受也不等于用户已读或全部必达渠道的权威回执。
