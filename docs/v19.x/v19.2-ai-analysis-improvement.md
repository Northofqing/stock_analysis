# v19.2 — AI 分析系统改进设计

> **Status:** Design
>
> **核心问题:** AI 分析可能是反向指标（IC=-0.0775），需要验证闭环

---

## 一、现状诊断

### 致命发现

```
src/pipeline/mod.rs:290-291:
IC=-0.0775, sentiment_score 方向性反转
高分票跑输统计基准 (≥80 胜率 40.9% vs <40 胜率 56.2%)

翻译: AI 高分票胜率 40.9%，低分票反而 56.2%
      → AI 分析质量比随机还差
```

### 核心问题

| 严重度 | 问题 |
|--------|------|
| P0 | AI sentiment 反向指标 (IC=-0.0775) |
| P0 | 三套并行的 LLM 基础设施（不共享配置/重试/路由） |
| P1 | 多 Agent 流水线已摘除但仍被调用 |
| P1 | 无 prompt 版本管理、无 AI 回测验证 |
| P2 | 错误降级过分宽容（全失败也产出噪音） |
| P2 | AI_DEBATE_ROUNDS=3 无效配置 |
| P3 | 5464 行 AI 代码，80% 处于半废弃状态 |

---

## 二、改进方案

### P0: AI 分析可回测验证（最重要，依赖 v19.1 SignalTracker）

```rust
// 与 SignalTracker 共用基础设施
struct AISuggestion {
    date: NaiveDate,
    code: String,
    ai_score: i32,
    ai_stance: String,    // bull/bear/neutral
    ai_model: String,
    price: f64,
    // 5日后回填
    return_5d: Option<f64>,
    direction_correct: Option<bool>,
}
```

目标: AI IC 从 -0.0775 转正，或确认 AI 分析不可用直接砍掉。

### P1: 统一 LLM 基础设施

废弃 GeminiAnalyzer 手写 reqwest，全部迁移到 LlmRegistry role-based 路由。

### P2: 清理死代码

- src/agent/multi_agent/（已摘除的多Agent流水线）
- src/bin/monitor/news_ai_shadow.rs（BR-172 dead_code）
- AI_DEBATE_ROUNDS=3 无效配置
