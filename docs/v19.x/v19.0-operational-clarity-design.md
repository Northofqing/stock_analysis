## 0. 文档定位

本文是 v19.x 主设计。它把 v18 写出来但未落地的抽象（DataEnvelope / AuditJournal / DecisionRecord）放一边，**先把运行层面 10 个实际痛点治好**，为后续 v20+ 把 v18 spec 真正落地提供运行基线。

若本文与 v18 active 冲突，**v18 优先**（v18 是远期架构目标）。但 v19.x 不被 v18 阻止推进——因为 v19 治的是运行痛，与 v18 抽象是正交的。

本文中的"完成 / 实现"指 PR 合入 + 单测 + 反向测试全绿 + log 实证。任何"完成"声明必须附 log 行号。

## 2. 设计原则

### 原则 1：可停止 > 永远跑

休市停轮询、数据源熔断、致命错误 halt。**默认就是停**。

### 原则 2：Banner 是真相源

不再 grep log 看状态。BannerSnapshot 是人读、CI 读、Prometheus 读的统一接口。

### 原则 3：错误码 > 错误字符串

每个失败 `ErrorCode { code, retryable, severity, retry_in_ms }`。CI 可消费、可聚合、可告警。

### 原则 4：可恢复 > 永不失败

CircuitBreaker 必备熔断 + 半开探测 + 恢复路径。"系统能不能自愈"比"系统能不能不挂"更重要。

### 4.2 `src/breaker/mod.rs`（PR-7 落地）

```rust
use std::sync::atomic::{AtomicU8, AtomicU32, AtomicI64, Ordering};
use std::time::{SystemTime, UNIX_EPOCH};

pub struct Breaker {
    state: AtomicU8,                    // 0=Closed, 1=Open, 2=HalfOpen
    consecutive_failures: AtomicU32,
    opened_at_ms: AtomicI64,
    cooldown_ms: u64,
    failure_threshold: u32,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum BreakerState { Closed, Open, HalfOpen }

impl Breaker {
    pub fn new(cooldown_ms: u64, failure_threshold: u32) -> Self { ... }

    pub fn try_acquire(&self) -> Result<(), ErrorCode> {
        match self.state.load(Ordering::Acquire) {
            0 => Ok(()),
            1 => {
                let now = now_ms();
                let opened = self.opened_at_ms.load(Ordering::Acquire);
                if now - opened >= self.cooldown_ms as i64 {
                    self.state.store(2, Ordering::Release);
                    Ok(())
                } else {
                    Err(ErrorCode::CircuitOpen { retry_in_ms: (opened + self.cooldown_ms as i64 - now) as u64 })
                }
            }
            _ => Err(ErrorCode::CircuitOpen { retry_in_ms: 0 }),
        }
    }

    pub fn record_success(&self) {
        self.consecutive_failures.store(0, Ordering::Release);
        self.state.store(0, Ordering::Release);
    }

    pub fn record_failure(&self) {
        let n = self.consecutive_failures.fetch_add(1, Ordering::AcqRel) + 1;
        if n >= self.failure_threshold {
            self.state.store(1, Ordering::Release);
            self.opened_at_ms.store(now_ms(), Ordering::Release);
        }
    }
}
```

**应用点**：
- `src/data_provider/fallback.rs:208-213` 每次 fetch 前 `breaker.try_acquire()`，失败 `record_failure()`，成功 `record_success()`
- `src/news/aggregator/feed.rs` 每个 feed 同样
- banner 实时反映 `BreakerState`

### 4.3 `src/monitor/mode.rs`（PR-1 落地）

```rust
use chrono::Local;

pub enum RunMode {
    Active,      // 9:30-15:00 A 股交易时段
    Quiet,       // 休市 / 人工 quiet
    Halted,      // 致命错误，需人工恢复
}

impl RunMode {
    pub fn from_now() -> Self {
        let now = Local::now();
        if crate::calendar::is_trading_day(now.date_naive())
            && now.time() >= chrono::NaiveTime::from_hms_opt(9, 30, 0).unwrap()
            && now.time() < chrono::NaiveTime::from_hms_opt(15, 0, 0).unwrap()
        {
            Self::Active
        } else {
            Self::Quiet
        }
    }

    pub fn should_fetch(&self, source: &DataSource) -> bool {
        match self {
            Self::Active => true,
            Self::Quiet => source.is_essential(),  // 仅 essential 源仍拉
            Self::Halted => false,
        }
    }
}
```

**关键改变**：
- 休市 monitor 不再"等交易时段... 失败、失败、失败"
- banner 显示 `Mode::Quiet` + `quiet_reason: "休市 (2026-07-20 09:30-15:00)"`
- 数据源失败不再积累（Quiet 时不 fetch）
- log 噪音预计降 80%

### 4.4 `src/error/mod.rs`（PR-3 落地）

```rust
use crate::breaker::DataSource;

#[derive(Debug, Clone, PartialEq)]
pub enum ErrorCode {
    BannerUnavailable { retry_in_ms: u64 },
    CircuitOpen { source: DataSource, retry_in_ms: u64 },
    DataSourceFailed { source: DataSource, retryable: bool, retry_in_ms: u64 },
    QuietModeActive { reason: String },
    Halted { reason: String },
    TestModeActive,
}

impl ErrorCode {
    pub fn retryable(&self) -> bool {
        match self {
            Self::BannerUnavailable { .. } => true,
            Self::CircuitOpen { .. } => true,
            Self::DataSourceFailed { retryable, .. } => *retryable,
            Self::QuietModeActive { .. } => false,
            Self::Halted { .. } => false,
            Self::TestModeActive => false,
        }
    }

    pub fn severity(&self) -> Severity {
        match self {
            Self::BannerUnavailable { .. } => Severity::High,
            Self::CircuitOpen { .. } => Severity::Medium,
            Self::DataSourceFailed { retryable: false, .. } => Severity::High,
            Self::DataSourceFailed { retryable: true, .. } => Severity::Low,
            Self::QuietModeActive { .. } => Severity::Info,
            Self::Halted { .. } => Severity::Critical,
            Self::TestModeActive => Severity::Info,
        }
    }
}

pub enum Severity { Info, Low, Medium, High, Critical }
```

## 9. 风险与诚实交代

### 风险 1：BannerSnapshot 落地可能影响现有 ~13 处 `let _ = notify::push_governor` 调用

PR-2 替换 `Mutex<Option<BannerCtx>>` 涉及多处 `current_banner()` 调用方。**每个调用方必须明确写明"BannerSnapshot 是 None 时的行为"**——这是之前隐式吞错的来源。

### 风险 2：PR-7 CircuitBreaker 可能影响实时行情

如果用错阈值（`failure_threshold=3` 太小），正常网络抖动会被熔断。**默认 `failure_threshold=10`、`cooldown_ms=60_000`（60s）**，实测后再调。

### 风险 3：PR-4 log rotation 用 tracing-subscriber 可能引入新 crate

`tracing` 是事实标准的 Rust log crate，**可选**：如果不想加新 crate，用 `log` + 自写 rotate 逻辑也行。

### 风险 4：v19.x 治不了 v18 spec 的根本问题

v18 的 `AuditJournal` / `DataEnvelope` 不落地，**v19.x 不补这个**。v19.x 只是让运行不再痛，**v18 落地是 v20+ 的事**。

### 诚实交代：v19.x 的预期效果不一定能完全实现

8 小时 log < 5,000 行是估算。如果用户使用模式（多 PushKind 推送）实际值可能更高。**每个 PR 合入后必须实测 log 指标，达不到的 PR 不进下一 PR**。
