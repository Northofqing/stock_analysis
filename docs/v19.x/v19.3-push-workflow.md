## 二、本次补全的接线（BR-223）

### 1. A-02 AuctionRepush（集合竞价优选重推）

- v13.10.1 因"候选台统一承载"停用，调用被注释（main.rs:6782-6798 遗留死代码）
- **恢复**：9:20-9:25 竞价窗口内，复用统一网关候选链路 `load_real_candidate_batch()`，Strong 档优先 + 热度降序取 Top5
- `is_legacy_v17_5` 移出 AuctionRepush（剩 3 个 legacy：CandidateTriggered/CandidateInvalidated/VirtualWatch）

### 2. P-05 CandidateBoard + 候选失效 diff

- **重建 dispatcher**（v17.x 清理时被删，`format_candidate_board` 只剩测试调用；候选台 5 次投递记录停在 07-17）
- **失效 diff（新规则）**：每次推送前把候选 code 集追加落盘 `data/candidate_board_snapshot/<date>.jsonl`（每行一轮），与上一轮 diff；上轮有本轮无 → `push_candidate_invalidated`（renderer 早已存在，第一次被生产调用）
- 首次运行无快照 → 不推失效（幂等）

### 3. 盘后大宗交易（新数据链路）

- **新 `BlockTradesGateway`**（src/data_gateway/block_trade.rs，dragon_tiger.rs 模式）：
  - 数据源：上游 magic-eastmoney-rs `BlockTrades` trait（东财 RPT_DATA_BLOCKTRADE，按代码查询）
  - 聚合证据 = 首个成功真实批次的 provenance（不合成 batch_id，遵守 BR-164）
  - 逐代码查询 + 失败隔离（单代码失败不阻断其余）
- **盘后复盘流程内**对自选（STOCK_LIST）+ 持仓代码集扫描：
  - 创业板（300/301）/ 科创板（688）协议大宗 → `BlockTradeIntradayConfirm`（Agreed/Gem|Star/实时确认）
  - 北交所（8xx/4xx/920） → `BlockTradePriceRange`
- 两个 dispatcher 的注册面（descriptor/v14/cooldown）早已存在，本次补齐生产者

### 4. A-11 IpoCatalyst（IPO 产业链催化）

- 数据源：`src/news/ipo/supply_chain.rs` 静态表（10 家 pre-IPO 公司 + 关联 A 股代码/关系）
- 每日一次推送阶段状态 + 关联受益票；推送正文如实标注"静态表，阶段变化需人工更新，非实时事件"
- **IpoListingApproval / IpoProspectus 保持 no_producer**：真实过会/招股书数据源未到位，启动时 Once banner 声明（CLAUDE.md §4d）

## 三、数据门依赖（行情恢复后自动恢复）

以下模板已完整接线，但受 **L5 治理 `data_quality` 门**约束（普通业务 profile 最低数据模式 Degraded）：

| PushKind | 阻塞原因 |
|---|---|
| `HoldingPlan` / `T0Advice` / `CloseCall` / `PositionReview` 等 | Quote 能力未建立 → DataMode Unsafe → 拒绝推送（fail-closed 设计） |

修复链（2026-08-05 已完成上游侧）：坏 TDX 服务器剔除（a8ff873）→ 腾讯/新浪 fallover 恢复 Quote → 数据模式转 Degraded/Full → 上述模板自动恢复推送。**需要一次真实盘中运行验证。**
