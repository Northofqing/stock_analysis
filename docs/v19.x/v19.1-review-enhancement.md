# v19.1 — 复盘系统增强设计

> **Status:** Design
>
> **核心目标:** 复盘从"投递审计"升级为"业绩复盘" — 从追踪"发没发"变成验证"对不对"

---

## 一、现状诊断

### 1.1 当前复盘做了什么

```
monitor --review 执行流程:
├── 9 个 ReviewTask (R02/R03/R04/R05/R06/R08/R09/A10/A01)
├── 分区: SourceOnly(6个) vs AccountRequired(3个)
├── 调度引擎: Pending → Waiting → Retry(1m/5m/15m) → Terminal
├── 审计链: SHA-256 哈希链 + JSONL + 跨进程文件锁
└── 输出: 推送投递是否成功 (Delivered/NoData/Failed/Disabled)
```

**生产级代码: 1025行调度引擎 + 1204行测试**

### 1.2 核心问题

```
当前复盘:  信号发出了吗？ → Delivered/NoData/Failed
应该是:    信号发对了？   → 涨了还是跌了？赚了多少？

R05 (信号复盘) 当前状态:
  review_batch.rs:1184-1186 → Disabled
  reason: "no append-only signal-delivery-execution-settlement outcome source"

翻译: 信号发出后没有记录后续收益 → 复盘系统不知道信号是否正确
```

### 1.3 复盘能力缺口

| ReviewTask | 名称 | 状态 | 缺口 |
|------------|------|------|------|
| R02 | 大盘复盘合同 | Disabled | 无完整大盘批次 |
| R03 | 持仓行业K线 | AccountRequired | 需真实账户水印 |
| R04 | 龙虎榜 | Working | 等21:00后数据 |
| **R05** | **信号复盘** | **Disabled** | **无信号→收益记录** |
| R06 | 失败分类复盘 | Disabled | 无失败证据源 |
| R08 | 事件日历 | Working | — |
| R09 | Provider Top-N | Working | 等15:35后数据 |
| A10 | 产业链轮动 | Working | — |
| A01 | 虚拟观察K线 | Working | — |

**9个任务中3个永久禁用 (33%)，R05是最关键且最该激活的。**

## 二、改进设计

### 2.1 核心理念

```
改进前 (当前):
  信号 → 推送 → 审计(发了没) → 结束

改进后 (目标):
  信号 → 推送 → 审计(发了没) → 记录期待 → N天后回填收益 → 复盘(对了没)
                                         ↓
                                   信号追踪器 (SignalTracker)
```

### 2.2 新增模块: `src/review/signal_tracker.rs`

```rust
/// 信号追踪记录 — 推送时写入，review 时回填
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SignalRecord {
    pub signal_date: NaiveDate,
    pub code: String,
    pub push_kind: String,
    pub direction: String,        // "bullish" / "bearish" / "neutral"
    pub price_at_signal: f64,
    pub source: String,
    pub identity_hash: String,
    // ↓ review 时回填
    pub price_after_5d: Option<f64>,
    pub return_5d: Option<f64>,
    pub direction_correct: Option<bool>,
    pub backfill_date: Option<NaiveDate>,
}

pub struct SignalTracker {
    dir: PathBuf,
}

impl SignalTracker {
    /// 推送时记录信号
    pub fn record(&self, code: &str, push_kind: &str,
                  direction: &str, price: f64, source: &str) -> Result<()>;

    /// review 时回填 N 天前的信号收益
    pub fn backfill(&self, signal_date: NaiveDate,
                    market: &MarketDataGateway) -> Result<Vec<SignalRecord>>;

    /// 统计 N 天前的信号胜率
    pub fn win_rate(&self, signal_date: NaiveDate,
                    market: &MarketDataGateway) -> SignalStats;
}

#[derive(Debug, Clone, Serialize)]
pub struct SignalStats {
    pub date: NaiveDate,
    pub total_signals: usize,
    pub resolved: usize,
    pub correct: usize,
    pub win_rate: f64,
    pub bullish_win_rate: f64,
    pub bearish_win_rate: f64,
    pub avg_return_5d: f64,
}
```

**存储位置:** `data/signal_tracker/YYYY-MM-DD.jsonl`

### 2.3 接入点

在 `push_governor_v3` 调用处埋入 record：

```rust
// 推送成功时，同时记录到 signal_tracker
fn push_and_track(code: &str, kind: PushKind, direction: &str,
                  price: f64, text: &str) {
    push_governor_v3(text, kind, ...);  // 原有

    signal_tracker().record(  // 新增: 一行调用
        code, kind.as_str(), direction, price, "monitor"
    );
}
```

### 2.4 新增 ReviewTask: R10

```rust
ReviewTask::R10,  // "signal_verification"

// ALL 从 9 → 10
pub const ALL: [Self; 10] = [
    Self::R02, Self::R03, Self::R04, Self::R05,
    Self::R06, Self::R08, Self::R09, Self::A10,
    Self::A01, Self::R10,
];
```

R10 的 review 逻辑：

```rust
fn run_signal_verification(context: ReviewRunContext) -> ReviewTaskOutcome {
    let signal_date = context.business_date() - Duration::days(5);
    let stats = SignalTracker::new()
        .win_rate(signal_date, &MarketDataGateway::new());

    if stats.resolved == 0 {
        return ReviewTaskOutcome::no_data("no signals found");
    }

    // 推送复盘总结到飞书
    let summary = format!(
        "📊 信号复盘 ({})\n\
         胜率: {:.1}% ({}/{})\n\
         看多: {:.1}% 看空: {:.1}%\n\
         平均收益: {:+.2}%",
        signal_date, stats.win_rate * 100.0, stats.correct, stats.resolved,
        stats.bullish_win_rate * 100.0, stats.bearish_win_rate * 100.0,
        stats.avg_return_5d * 100.0,
    );
    push_governor_v3(&summary, PushKind::ReviewDaily, ...);

    ReviewTaskOutcome::delivered(stats.resolved)
}
```

## 五、验收标准

```
Phase 1: ✓ 推送后 data/signal_tracker/ 有记录
          ✓ 5天后可回填收益
          ✓ SignalStats 计算正确

Phase 2: ✓ R10 ∈ ReviewTask::ALL
          ✓ R10 不被 disable
          ✓ review 时 R10 正常执行

Phase 3: ✓ 飞书/微信收到每日复盘推送
          ✓ 周度聚合数据正确
```
