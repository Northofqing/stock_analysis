# Independent local reliability tools — staged, not installed

These Python 3.9-compatible tools do not initialize or migrate a database, obtain provider data, send messages, adjudicate orders or restart monitor. This delivery stages source, fixtures and a watchdog plist. None of the installation, runtime acceptance or production archive/prune commands below has been executed. The fallback is computer-visible local persistence; mobile/Feishu fallback remains unconfigured. Existing counted business sends retain `push_counted_with_binding` ownership and Uncertain remains unknown/human-only.

## Stable CLI and artifacts

All filesystem arguments must be absolute, without `..` or symlink components. Private existing output/archive roots must belong to the invoking user and have mode 0700. New output roots are created 0700; artifacts are 0600. Output leaves are exclusive, except watchdog `state.json`/`latest.json`, which atomically replace private regular leaves after fsync. stdout/error messages are allowlisted and never include child stderr, environment or arbitrary health fields.

- `monitor_watchdog.py --runtime-root ABS --calendar ABS --output-root ABS [--probe-timeout-seconds 5] [--observed-at RFC3339] [--extra-holiday YYYY-MM-DD ...]`: fixed `<runtime>/target/release/monitor --health --json`, cwd runtime, 64 KiB combined stdout/stderr cap and bounded timeout (maximum 30 seconds). Exit 1 from the child is valid unhealthy data; 2/other exits, malformed/missing schema, spawn failures, timeout and output overflow become P0 `probe` unavailable incidents. Watchdog exits 0 after local persistence without current P0, 1 with current P0, 2 on local output/input failure; overlap exits 0 without probing. No `.env` is loaded.
- `rotate_push_log.py --runtime-root ABS --archive-root ABS [--before YYYY-MM-DD] [--retention-days 30] [--archive] [--prune-verified-md] [--max-dates 1] [--max-files 2000] [--lock-wait-seconds 2] [--time-limit-seconds 30] [--observed-at RFC3339] [--output ABS]`: default dry-run under the **existing** `.push_log.lock` flock; no lock creation/replacement. Before is exclusive and always clamped to today. `--archive` copies bytes; pruning additionally requires `--prune-verified-md`. Dates/JSON/lock/today/future stay in place. Exit 0 emits evidence, 2 rejects unsafe/unavailable inputs. Default one actionable date; maximum 10 actionable dates/10000 Markdown files per date/64 MiB tar, 10s lock wait and 120s runtime. A date above bounds is refused rather than partially archived. Runtime bound is checked between bounded file/archive steps; a single fsync cannot be forcibly timed out.
- `reliability_quality_screen.py --db ABS --delivery-db ABS --push-log ABS --calendar ABS --output ABS [--archive-root ABS] [--price-authority-evidence ABS] [--paper-evidence ABS] [--max-rows 10000] [--max-files 20000] [--observed-at RFC3339]`: version 1 private exclusive report, exit 0 once persisted (including explicitly unavailable rules), 2 on output/input failure. Every rule records actual rows/files and truncation. For R2, `--max-files` bounds combined live leaf read attempts plus archive-member read attempts, and separately bounds archive-date validation attempts. A manifest is read first (<=8 MiB); a whole date exceeding the remaining member budget is refused before reading its tar (<=64 MiB), with explicit unavailable/truncated evidence. Every admitted archive is fully reread and verified before processing any member. `files_read` counts successful physical live/manifest/tar reads; `processed_occurrences` counts successfully loaded live leaves and fully verified archive members, including copies before original-path collapse. `read_accounting` separately records source/metadata/member attempts, successes and returned bytes, and declared member counts; failed reads consume attempts but report no unknown byte count as measured. Manifest/tar metadata are separately budgeted, so physical `files_read` can exceed the member/leaf budget without concealing reads. Reads use consistent private logical backups through the existing weekly `read_only_backup` seam: source `mode=ro`, `query_only`, `BEGIN`; live WAL is included, never `immutable=1`. Each backup records source path, logical snapshot SHA-256, schema hash and user_version. The full backup can cost more than bounded rule scans; existing helper bounds each backup at 30s.

Watchdog uses health `status` and `runtime_snapshot` version 2. Process absence/invalid identity/mismatch/missing heartbeat/future heartbeat or age >600s is immediate P0; no restart-resetting initial grace exists. Approximate stale-heartbeat detection bound is 600s plus one 60s poll. Active Morning/Afternoon Quote missing, or unavailable data evaluation, escalates after two consecutive polls no more than 120s apart, with same boot/date/session/reason. A gap, boot change, lunch or date change resets the streak. Quote-only incidents are suppressed during closed/lunch/after-hours and remain P1 in Auction pending an auction freshness contract. Calendar coverage is taken from the checked-in `# year=` declaration and dates, not weekdays alone; malformed/out-of-coverage calendar is P1/unavailable. Explicit additional holiday dates are separately hashed; installation must mirror any runtime additions without exposing `.env`.

Account frozen/incomplete/unavailable is scoped P1; missing non-Quote capabilities, raw news recovery and durable manual review are P2. The overall fail-closed health status remains visible in `latest.json`. Dedup identity is SHA-256 of rule/reason/Shanghai date/boot hash. Events occur on first/changed observation, hourly unresolved P0 reminders and one verified scope/session recovery. A failed/unknown probe cannot establish recovery. Failed event writes do not advance dedup state. `events/<sha256>.json` is immutable; `state.json`, `latest.json`, and `self-check-YYYY-MM-DD.json` are version 1. The daily artifact records only a local write/read check, not mobile delivery. Event write succeeds before state publication; a failure between event and state can yield repeat local evidence on retry (no physical send is attempted).

Each archive date has `<date>.tar` plus `<date>.manifest.json` schema 1: date, source_root, archive filename, archive byte count/SHA-256, entries with original relative path, bytes, SHA-256 and `[device,inode,size,mtime_ns,ctime_ns]`. A tar is published without overwrite before the manifest; both are fsynced and every member independently reread. Existing complete archives are fully validated on rerun, then skipped without occupying the actionable date batch: archive-only skips existing complete archives; pruning skips an existing archive when none of its listed Markdown sources remain. `skipped_dates` records verified manifest hashes, listed sources remaining and unlisted Markdown; `unexamined_dates` and `truncated` identify dates not yet inspected after the actionable batch fills. No-Markdown dates are skipped. Dry-run is a stateless preview and can repeat the same work dates. Unlisted/new sources remain untouched and cannot be added to an already immutable date archive by this release. A crash leaving tar without manifest requires human review and is never overwritten or used to prune. Pruning verifies the full archive and every still-present original before any unlink, then rechecks each original and pinned directory/lock identity before unlink/fsync. Missing manifest members permit crash-resume; changed originals refuse the run, new/unlisted originals remain untouched. JSON is never removed; archive-backed counted JSON reads require a separate owner/reader contract.

Quality R2 labels exact byte-body duplicates separately from physical receipts; live and rotated copies of the same original relative path count once. Any original path with differing loaded hashes is removed from every candidate group; `content_conflicts` retains both revisions’ hashes, sizes and live/tar-member locations as raw unavailable evidence. Counted pending/committed artifacts join as one diagnostic attempt after identity/content/pending hash checks; delivery-audit binding remains explicitly unavailable in this view. Physical R2 requires schema 9 joins, exact canonical envelope/result SHA-256 and nested content/source hashes, matching attempt/fence and typed receipt columns. Repeated `(provider,channel,platform_message_id)` observations collapse; distinct Accepted IDs for one decision are candidates, including late-after-fence evidence. Unknown/Uncertain is never counted as delivered. Cross-decision physical content repeats and user reading remain unavailable.

R3 reports original IDs, creation/target dates, calendar hash and optional freeze provenance hashes. Creation on a weekend alone is not a candidate; malformed dates/out-of-coverage are explicitly unavailable. R1 retains raw Filled order audit facts but stays `unavailable_independent_same_day_price_authority` while `QualifiedTradingFactsGateway` is ContractNotDelivered. Self-asserted JSON (including same-day/tick/band/exception flags) cannot qualify a source. R5 retains bounded legacy paper rows when present but stays `unavailable_seeded_account_lot_evidence` until an existing seeded/account/lot-qualified reader/export exists. No ledger replay, pooled sell/buy inference, seed, invalidation, exclusion or cancellation is implemented here.

## Later installation and cutover

Installation is a separate runtime action. Inspect existing files/job first; stop if an existing watchdog belongs to a different release. Keep any old watchdog scripts/plist in a separate private rollback directory before replacement. Do not overwrite the installed monitor or bridge plist, their environment, config, activation or binary. This watchdog-only copy uses `runtime/bin/watchdog-a-share-holidays.csv`; it does not change monitor's source/config and does not require a monitor restart or activation resend.

After authorizing installation, run from the reviewed checkout with the actual absolute `reliability_source` path:

```bash
reliability_source=/Users/zhangzhen/.codex/worktrees/goal-first-delivery/stock_analysis
reliability_runtime=/Users/zhangzhen/.local/share/stock-analysis-runtime
/usr/bin/python3 --version

Confirm runtime/bin and logs already exist as real directories and all listed paths have no symlink components. For a reinstall, unload only the watchdog before copying its files. The first manual invocation can return 1 for a real P0; inspect its private artifacts before loading the job. `RunAtLoad=true`, `StartInterval=60`, no KeepAlive loop, launchd Umask=63 (decimal 077). Calendar and health binary paths are explicit. No monitor composition root participates.
