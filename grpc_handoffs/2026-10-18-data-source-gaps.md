## D1 板块主力净流入（f62）【P0】

### 用途

票的五维优先级里「板块强度」占 20%。现在这一维**基本拿不到分**——因为只拿到涨幅榜，拿不到资金流向榜。

### 现状（实测证据）

Mac 侧调用 `MarketRankings`，`fid=f62`：

```
[板块榜] f3=175 f62=0 persisted=175 errors=1
  ! 净流入榜 fid=f62: GrpcBridge data gateway failed reason_code=no_verified_batch
    provider=None retryable=false: gRPC MarketRankings 查询失败: 服务端内部错误
```

对端源码（`src/bin/grpc_market_server/grpc_server/delegate.rs`）里 `fetch_board_ranking` 是**硬编码**：

```rust
let _ = (fid, top_n);
Err(FetchFailure {
    message: "板块排行 provider 未返回可保真的 batch evidence",
    provider: None,
    reason_code: "no_verified_batch",
    retryable: false,
})
```

不是解析失败，不是上游超时，是**这一路根本没实现**。

### 需要什么

复用 `MarketRankings` op，把 `f62` 接上。数据源建议东财（`push2.eastmoney.com/api/qt/clist/get`，`fid=f62`，`fields=f12,f14,f3,f62`）。

返回字段保持现有 `BoardRankingFact` 契约：

| 字段 | 说明 |
|---|---|
| board_code | 板块代码 |
| board_name | 板块名称 |
| change_pct | 涨跌幅（f3） |
| **main_inflow** | **主力净流入（f62）— 就是这个缺的** |

### 验收标准

```
MarketRankings(fid="f62", top_n=30) 返回 30 条，main_inflow 非 NULL
Mac 侧 board_ranking_build --date <今天> 输出 f62=30 而不是 f62=0
```

### 没有的代价

Mac 侧不能推算（BR-222 禁止补 0），只能这一维留空 → 板块强度永远缺 20% 权重。

## D2 板块涨幅榜（f3）【P0】

### 用途

同 D1，板块强度维的另一半。

### 现状

同一个 `fetch_board_ranking` 硬编码 Err。Mac 侧已用**新浪概念板块**兜底（`vip.stock.finance.sina.com.cn/q/view/newFLJK.php?param=class`），拿到 175 个概念板块的涨幅。

**兜底的三个限制**：
1. 只有**概念**板块，没有**行业**板块（新浪行业板块 `newSinaHy.php` 拉过，但行业名在本地 `stock_concepts` 里逐名验证 0 匹配，拉进来只会挤占榜单）
2. 只有**实时快照**，没有历史（今天错过的就永远没有）
3. 新浪的板块代码（`gn_dfj`）与东财（`BK0493`）不通用，跨源无法对齐

### 需要什么

和 D1 同一个 op，`fid=f3` 返回行业板块 + 概念板块的涨幅榜。

### 验收标准

```
MarketRankings(fid="f3", top_n=100) 返回 100 条
board_code 用东财 BK 码或申万行业码（能稳定标识即可）
```

### 没有的代价

现在能跑，但只有概念、没有行业，且拿不到历史做回放。

## D3 板块成分股映射【P1】

### 用途

票的「板块强度」维要算，前提是**知道这只票属于哪个板块**。

### 现状

Mac 侧用本地 `stock_concepts`（1265 只票的概念标签）。问题是**命名对不上**：

| 本地标签 | 对端板块名 | `instr` 匹配 |
|---|---|---|
| 「AIGC概念」 | 「AIGC」 | ❌ |
| 「IP经济」 | 「IP经济」 | ✅ |
| 「数据确权」 | 「数据确权」 | ✅ |

实测 9 只观察票，**5 只匹配不上**（`board_score` 返回 None 而不是 0）。

### 需要什么

`BoardConstituents`（已有接口）反向用：给一个板块代码，返回成分股列表。Mac 侧拿全 175 个板块的成分股，就能建「票 → 板块」的反向索引，不再依赖命名匹配。

### 验收标准

```
BoardConstituents(board_code="gn_dfj") 返回该板块所有成分股代码
175 个板块全量拉一遍 ≤ 3 分钟
```

### 没有的代价

板块维覆盖率只有 4/9，其余票这一维永远缺。

## D4 产业链上下游（公司级）【P1】

### 用途

用户原话：「盘中密切关注该票的新闻、公告、**关联公司**」。当 A 出利好，B（A 的供应商/客户）会不会跟着动。

### 现状

F10 的 16 个分类里**没有客户/供应商**：

```
最新提示、公司概况、财务分析、股东研究、股本结构、资本运作、业内点评、
行业分析、公司大事、研究报告、经营分析、主力追踪、分红扩股、高层治理、
龙虎榜单、关联个股
```

Mac 侧已用 LLM 从「经营分析」的主营构成推出**商品级**上下游（600396 → 动力煤 0.95、天然气 0.55；300750 → 碳酸锂 0.90、新能源汽车 0.80），但：

- 拿不到**具体公司名**（"宁德时代的供应商是赣锋锂业"这种）
- 只能到行业/大宗商品级
- AI 推断必须标 `[AI推断·未核实]`，不能直接用于买卖

详见 `2026-10-18-related-company-data-request.md`（已单独提过）。

## D5 股权关联【P2】

### 用途

同一实控人 / 母子公司 / 参股关系 —— 这是最硬的传导。

### 现状

F10「关联个股」给的是：同大股东、同行业、股本相近、同地域。实测 600396 的「同大股东」列的是**香港中央结算有限公司、巴克莱银行**——这是**登记股东**（券商托管席位），不是实控人。

### 需要什么

实控人名称 + 控股股东 + 参股比例，最好能拿到「同一实控人」的全部上市公司列表。

### 用途
